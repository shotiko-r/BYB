# P2.2 Browse variation audit

Inspected the current mapper, provider, detail enricher, shared types, and existing fixtures. Existing fixtures did not include group identifiers. Search continues to use its existing mapping and optional aspect requests; it never requests item groups.

Verified against the official [Browse OpenAPI schema](https://developer.ebay.com/api-docs/master/buy/browse/openapi/3/buy_browse_v1_oas3.json) and a read-only production Browse response on 2026-10-23. The official [getItem](https://developer.ebay.com/api-docs/buy/browse/resources/item/methods/getItem) and [getItemsByItemGroup](https://developer.ebay.com/api-docs/buy/browse/resources/item/methods/getItemsByItemGroup) define the contract.

## Fields actually observed

- `primaryItemGroup.itemGroupId`, `.itemGroupType = SELLER_DEFINED_VARIATIONS`, `.itemGroupHref`, `.itemGroupTitle`, `.itemGroupImage`.
- `itemId` (REST identity containing the variation identity), `legacyItemId`.
- `localizedAspects[].name` / `.value`: the member's exact options.
- `price.value` / `.currency`, `image.imageUrl`, `additionalImages[].imageUrl`, `itemWebUrl`, `buyingOptions`.
- `estimatedAvailabilities[].estimatedAvailabilityStatus`, `estimatedAvailableQuantity` / `estimatedRemainingQuantity` where supplied. The documented `itemEndDate` is also honored when supplied.
- The current schema has no `variesBy` or separate member `legacyVariationId` response field. We do not parse or guess a legacy variation identifier.

Live listing `227133051766`, opened member `v1|227133051766|526414814372`, returned six members. Dimensions: `Color: Black, White`; `Storage: 128 GB, 256 GB, 512 GB`. Prices observed: USD 469.99, 619.99, 649.99, 699.99. Two distinct primary images and three explicitly out-of-stock members. The opened member matched Black / 256 GB. These are observations at audit time, not availability promises.

A separate live getItem audit confirmed `v1|318849109603|0` has no `primaryItemGroup` and a USD 152.00 item price; the single-item browser scenario replays that sanitized response.

The checked-in regression fixture is a whitelisted public subset of that response, excluding seller data, tokens, affiliate data, and descriptions. Browser verification replays sanitized production data; deterministic placeholder images verify layout and image URL changes without relying on CDN availability.

## Implementation boundary

Only `getProduct` detail calls read group identity and request `/item/get_items_by_item_group?item_group_id=...` through `EbayBrowseClient.get`. No arbitrary upstream HATEOAS URL is followed. Require a numeric group identifier and the documented seller-variation type. Each accepted member must explicitly match the requested group.

Dimensions are differing, sanitized `localizedAspects` present on every accepted member. No invented option names, combinations, or prices. Ambiguous duplicate combinations hide the group. At most 100 members, eight dimensions, 100 values per dimension, and 12 validated CDN images per member. Existing transport limits upstream responses to 1 MiB. Malformed members are discarded individually; unresolvable groups leave ordinary detail intact.

Cache: provider-instance memory only, marketplace + group ID key, ten-minute TTL, 250 entries. Only successful normalized groups are cached. Detail enrichment does not cache an optional group failure, allowing retry. Nothing writes variation data to the database.

Frontend starts at the exact current member if available. Otherwise the existing product stays visible until the shopper completes an explicit, real combination. Disabled options exclude impossible/out-of-stock combinations. Clear selections allows navigation between combinations that share no option values. Missing variant images retain the original gallery. Variant price/currency, availability, shipping, identity, and destination update only the local presentation; comparison offers remain the stored offers.

## Limits

Partial or ambiguous upstream groups can hide selectors. Groups exceeding the safe bounds are omitted or limited to the first 100 returned members; no pagination or invented remainder is presented. Unknown availability remains unknown. Cache snapshots can lag changing stock for up to ten minutes. No persistence, Trading API, search/discovery group lookup, or AliExpress changes.
