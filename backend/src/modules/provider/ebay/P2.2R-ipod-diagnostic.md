# P2.2R: exact production iPod mismatch diagnosis

Read-only snapshot on 2026-10-23. Product: `a76c7409-f577-4cac-a141-d1731991d29f`; listing: `358020906068`.

## Trace and selector failure

1. The persisted catalog search endpoint (repository-backed, without detail enrichment) returns external ID `v1|358020906068|626788065835`, USD 149.99. The public detail endpoint returns that same offer, enriched gallery/description, and no `variationGroup`.
2. `getItem`, with `fieldgroups=PRODUCT`, returns exactly that REST ID and USD 149.99. `legacyItemId=358020906068` identifies the common listing, not a particular variation. No legacy-ID fallback is necessary or safe here.
3. `primaryItemGroup.itemGroupId=358020906068`; type `SELLER_DEFINED_VARIATIONS`; href `https://api.ebay.com/buy/browse/v1/item/get_items_by_item_group?item_group_id=358020906068`.
4. The group endpoint returns 83 members. All 83 pass the existing mapper. All four dimensions are present on every member: Generation (3 values), Color (4), Condition (4), Storage Capacity (9). There are no partial/missing values for these dimensions, duplicate item IDs, or duplicate normalized selection combinations. There are 47 in-stock and 36 out-of-stock members. Three distinct primary images; each member provides six gallery images.
5. The actual complete group HTTP response is **1,714,036 bytes**. Existing `ebayJson` rejects anything above **1,048,576 bytes**, with `EbayError('malformed')`. Reproduced through the actual `EbayBrowseClient` and `EbayProvider`: detail succeeds, optional group lookup fails, `variationLookupFailed=true`, no public group.
6. The detail enricher preserves the ordinary DB offer and does not expose the retry marker. Frontend `productVariationGroup` requires `product.variationGroup` with more than one variant; its absence makes the `<ProductVariations>` conditional false. This is the exact hiding condition for this case.

The ambiguity guard remains unchanged: `new Set(variants.map(member => JSON.stringify(member.selections))).size !== variants.length` hides an ambiguous group. This guard does **not** fire for the captured response. No safe normalization change is needed. Localized `Condition` values distinguish Good from Very Good; top-level item `condition` is a separate eBay condition label and is not substituted for this selector.

With the group restored, existing frontend selection logic retains the exact current member's 149.99 and uses that member's URL; explicitly choosing Good changes the price to 139.99 and URL to `var=626788065832`. ## Description boundary

The seller HTML places unrelated products and prices after the separate decorated heading `·  ·  ·   Suggested Products   ·  ·  ·`. Existing HTML-to-text sanitization removes executable markup, but keeps this advertising text. The live public description is 4,548 characters; corrected detail text is 3,898 characters and preserves the actual description and preceding seller terms.

The filter runs only inside eBay detail plain-text mapping. It recognizes an exact heading in its own separated paragraph, allows the observed decorative separators, and truncates from that paragraph onward. Recognized headings: Suggested Products, Related Products, Similar Products, Similar Items, You May Also Like, Other Items. It leaves inline mentions, included-item prose, uncertain line boundaries, and a heading at the very beginning unchanged. Description text is never used for pricing.

## Smallest fix and scope

- `ebayJson` accepts an internal bounded response-size argument, defaulting to the original 1 MiB.
- Only the exact `/item/get_items_by_item_group` client path uses 2 MiB. OAuth, getItem, search, timeouts, redirects, normalization, cache, and fallback behavior retain their existing limits/logic.
- Existing frontend selection/price/gallery/CTA logic requires no behavior change.
- Search, discovery, AliExpress, schema, persistence, environment configuration, and deployment remain untouched.

After the fix, a fresh live client audit accepted the same 1,714,036-byte group and returned 83 normalized members at the exact current item's 149.99. The checked-in fixture is a whitelisted public subset; synthetic common-description padding reproduces the measured transport size in regression tests without storing a raw seller/provider payload. The description HTML example in the fixture is synthetic with the exact observed heading decoration.
